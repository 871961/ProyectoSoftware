===============================================================================
❌ SOLUCIÓN DE PROBLEMAS COMUNES
===============================================================================

PROBLEMA 1: Error "No such column edad_diagnóstico"
-------------------------------------------------------
CAUSA: La base de datos no se actualizó correctamente
SOLUCIÓN:
   1. Ejecuta: psql -U postgres -d medhistory -f database/fix_columna_edad.sql
   2. O ejecuta manualmente en pgAdmin:
      ALTER TABLE antecedentes_familiares 
      RENAME COLUMN "edad_diagnóstico" TO edad_diagnostico;


PROBLEMA 2: "Failed to open stream: config/database.php"
-------------------------------------------------------
CAUSA: Los archivos PHP no se actualizaron por Git
SOLUCIÓN:
   1. Verifica que todos los DAO tengan líneas como:
      require_once __DIR__ . '/../config/database.php';
   2. Si no, haz: git fetch origin y git reset --hard origin/main


PROBLEMA 3: "Error al cargar antecedentes: SyntaxError"
-------------------------------------------------------
CAUSA: El navegador está usando archivos JavaScript antiguos en caché
SOLUCIÓN:
   1. Presiona Ctrl + Shift + Delete
   2. Selecciona "Cached images and files"
   3. Click en "Clear data"
   4. Recarga con Ctrl + F5


PROBLEMA 4: No veo la nueva interfaz de "Mis Pacientes"
-------------------------------------------------------
CAUSA: Git no descargó frontend/static/js/mis-pacientes.js
SOLUCIÓN:
   1. Ejecuta: git status
   2. Si no ves el archivo, ejecuta: git pull --rebase
   3. Si aún no aparece, pídeme el archivo mis-pacientes.js


PROBLEMA 5: Los pacientes no cargan / "No autorizado"
-------------------------------------------------------
CAUSA: La sesión no está iniciada o expiró
SOLUCIÓN:
   1. Cierra sesión (Logout)
   2. Inicia sesión de nuevo como médico
   3. Si persiste, verifica que en datos_prueba.sql hay médicos con tipo 'general'


PROBLEMA 6: Chat médico muestra "falta CHAT_ENCRYPTION_KEY"
-------------------------------------------------------
CAUSA: No está configurada la clave de cifrado del chat
SOLUCIÓN:
   1. Genera una clave segura (32 bytes):
      PowerShell:
      [Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 } | ForEach-Object { [byte]$_ }))
   2. Configura la variable de entorno en Apache (VirtualHost o httpd.conf):
      SetEnv CHAT_ENCRYPTION_KEY "<TU_CLAVE_BASE64>"
   3. Reinicia Apache y prueba de nuevo.

NOTA DE SEGURIDAD PARA ENTORNO SANITARIO
-------------------------------------------------------
- Usa HTTPS obligatorio en despliegue real (TLS 1.2+).
- Mantén la clave de cifrado fuera de Git y rota la clave según política interna.
- El chat está diseñado para coordinación asistencial: evita incluir datos clínicos innecesarios.
